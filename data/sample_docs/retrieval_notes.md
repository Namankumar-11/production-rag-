BM25 is used for lexical, keyword-based retrieval in search systems. It is a statistical ranking function built on term frequency and inverse document frequency, and it excels at exact-match signals such as product codes, error messages, acronyms, and rare proper nouns that dense embedding models can struggle to represent well. BM25 does not understand meaning or synonyms; it only understands overlapping terms between the query and the document.

Dense vector retrieval embeds both the query and each document into a shared vector space using a neural embedding model, then ranks documents by similarity, usually cosine similarity or inner product. This captures semantic meaning, so a query about "automobiles" can retrieve a document about "cars" even without shared vocabulary. Its weakness is precisely the cases where BM25 is strong: rare exact terms can get lost in the embedding space.

Hybrid retrieval systems combine both approaches to get the benefits of each. Reciprocal rank fusion combines search results from multiple retrievers by summing, for each document, the value 1 divided by (a constant k plus the document's rank in each individual ranked list). Because it operates on rank position rather than raw score, it avoids the problem of combining scores that live on different, incomparable scales, which is the main challenge when merging a BM25 score with a cosine similarity score.

A cross-encoder does differently from a bi-encoder in how it processes the query and document. A bi-encoder, used for the initial fast retrieval stage, encodes the query and each document completely independently into fixed vectors and compares them afterward, which is what makes it fast enough to search over a large corpus. A cross-encoder instead takes the query and a candidate document together as a single joint input and outputs one relevance score directly, which is much more accurate because the model can attend across both texts simultaneously, but far too slow to run over an entire corpus. The standard production pattern is to use a bi-encoder for fast first-stage retrieval over the whole corpus, then a cross-encoder to rerank only the small set of top candidates.
